# ADR-006：明确操作反馈与选择配置邮件目标

- 日期：2026-10-11
- 状态：用户已确认范围与邮件再次发送选择；书面规范待审，尚未实现
- 上游：proposal §8/N01–N06、design §1.6、web-operations §7、Task19–21

## 问题与用户意图

现有查询若返回同状态，提示文案保持原样；预览成功只更新下方内容，不给就近完成提示。维护者难以判断按钮是否生效。邮件只展示人数且固定发送全部配置邮箱，无法选择自己或导师。

用户明确仅勾选配置中的邮箱，不新增按收件人防重复功能；允许同版本使用新请求、独立确认再次邮件推送，同时保留同一次请求去重、断线不自动重发和飞书原重复限制。

## 方案比较

| 方案 | 判断 |
|---|---|
| 现有 React 反馈 + 配置邮箱子集 + 复用一次 SMTP 提交 | 采用；与目的匹配，现有模块和测试可复用，能够只发送所选地址 |
| 增加逐收件人账本与重复阻断、逐人 SMTP 调用 | 用户已明确不添加；增加接口/状态复杂度，超出本轮范围 |
| 收件人管理后台、临时任意地址及新组件/通知服务 | 本轮不采用；配置固定的本机工具已有必要能力，不增加依赖或配置编辑流程 |

## 决策

1. 查询/预览就近显示动作加载、完成/无结果和失败；本次查询时间与服务器执行时间区分。仅主动预览成功定位并聚焦正文，继续沿用请求 ticket/AbortController 防竞态。
2. 配置邮箱只在认证接口返回，浏览器初始不选择任何邮件目标；确认显示实际地址。后台严格校验配置子集，缺失目标拒绝，不回退全量。
3. DeliveryRequest/操作记录增加 email_recipients；排序规范化后进入指纹和持久记录，执行仅使用该快照。复用既有 send_email 的 recipients 参数，所选列表一次提交 SMTP，继续按渠道汇总结果；CLI 保持配置全量发送。
4. 解除邮件同版本跨请求阻断，用户使用新键、独立确认可以主动再次发送。保留请求去重、活动槽、版本校验、发送不确定性、无自动重发和飞书防重复。确认显示可能产生重复邮件；未知结果建议先核实，但不冒充明确拒绝。
5. 缺少目标的旧记录返回 null 并显示未记录，不补造历史。旧邮件请求缺新增字段返回 400；新前后端配套启用。生成/日报查询/源采集及产品版本本阶段不改。
6. 沿用 ADR-005 严格 TDD 与已有 pytest/Vitest/Testing Library/Playwright，不新增框架或通用服务。规范和计划审查后再开发，文档不冒充已实现功能。

## 冲突与后果

- v1.2 的整邮件渠道重复阻断是已发布历史行为；本次按用户最新确认修订。请求级幂等依旧执行，不能把主动新请求和响应丢失的原请求混为一谈。
- 再次邮件发送可造成重复，这是用户明确选择的交互能力；页面展示本次目标和风险，不自动执行。SMTP 受理不保证收件箱展示。
- 具体邮箱属于受保护的操作目标数据，不是上游凭证；允许认证维护者查看，不进入公开历史 GET、日志或真实仓库 fixtures。
- 无需改 Notifier 公共签名、DailyReport schema、源平台适配或增加依赖；仅围绕反馈、目标与相关兼容边界改动。
