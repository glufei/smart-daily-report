# v1.2 真实后端接入 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 浏览器触发真实采集生成、预览固定版本，再独立推送 SMTP/飞书；以先失败测试和真实外部证据交付 v1.2。

**Architecture:** 复用既有 run_report(dry_run=True)、Collector、SQLite、ReportView 和 Notifier；FastAPI 接受操作后以同步 BackgroundTasks 执行阻塞 I/O，单进程仅一个活动 Web 操作。独立 SQLite 操作记录保存幂等和渠道结果，GET 不触发业务执行，React 只调用本项目 API。

**Tech Stack:** Python ≥3.11 / pytest / httpx / FastAPI / SQLite；React + TypeScript + Vite + Zod；Vitest + Testing Library + Playwright。沿用现有锁定版本，不添加 Jest、Redis、Celery、SDK 运行依赖或模型调用。

**Spec:** `specs/proposal.md` R01–R12；`specs/design.md` §1.4–§1.5、§8.2；`specs/adrs/005-superpowers-tdd.md`；`specs/contracts/web-operations.md`、`interfaces.md`、`data-models.md`；`specs/tasks.md` Task 15–18。规范已获用户确认；飞书采用已授权清单的所选日期完成任务，已同步规范。本计划已获用户确认，采用 Native 本会话逐项执行；实现状态以任务记录和 TDD 日志为准。

## Global Constraints

- 严格遵循 TDD，必须先编写失败的单元/集成测试用例，再实现通过测试的业务代码。每个新增/修改业务行为先展示并运行 RED，原因是缺失业务行为而非语法/依赖错误；GREEN 后才重构。
- 本机 127.0.0.1:8000，单 Uvicorn worker、无 reload；Origin 恰为 http://127.0.0.1:5173 和 http://127.0.0.1:4173。操作模式 GET/POST/OPTIONS，允许 Authorization/Content-Type/Idempotency-Key，不使用 Cookie 或通配 Origin。
- `--database` 只读模式与 `--config` 操作模式互斥；前端 VITE_API_MODE 为 readonly/operations，默认 readonly。操作 Token 为 DAILY_REPORT_WEB_TOKEN，至少 32 字符，前端只存内存，上游秘密仅服务器持有。
- 请求日期严格 YYYY-MM-DD；请求键 UUID v4；HTTP 202 仅为接受操作。同键同内容不重复执行，同键不同内容/其他活动操作/版本变化/不可重发渠道为 409。
- 生成不发送，GET 不执行采集/生成/写历史/通知；推送使用预览版本快照及固定服务器目标。accepted/partial_failure/unknown 渠道不整渠道重发；断线与进程重启不自动重放。
- 查询超时保持 10 秒；操作观察 GET 间隔 2 秒、最多 120 秒，停止观察不是取消后端操作。日期切换和迟到响应不改变新日期内容。
- Python 总业务覆盖率 ≥90%；新增/修改前端业务模块 lines/statements/functions/branches 分别 ≥90%；全部测试、typecheck、build、Playwright 通过。
- Node `^22.12.0 || ^24.0.0 || >=26.0.0`；已验证 Python 3.12.14、Node 24.15.0。用 `.runtime/venv/Scripts/python.exe`，不使用失效的旧 `.venv`。
- 离线测试不连接真实 GitHub/飞书/SMTP；真实验收使用实际工作日、授权来源及配置目标，并核对实际邮件/群内收到。敏感消息、真实数据库、凭证和原始联调输出不入 Git。

## Review Focus

1. 同一 Idempotency-Key 的渠道顺序变化应视为同一次请求，空数组/重复渠道/陌生字段必须拒绝；测试归 Task 15-B / 17-C。
2. POST 已接受但响应丢失、刷新后 current 与旧日期结果混用，不能重交或展示错日报；测试归 Task 15-E / 17-D。
3. CLI 在预览后覆盖同日期日报，或在两个渠道之间覆盖，推送必须拒绝未确认版本或保持已捕获同一快照；测试归 Task 17-C。
4. SMTP 已发送、QUIT/退出连接失败，或部分收件人被拒绝，不应重发已接受内容；测试归 Task 17-A。
5. 操作记录库无法写入/损坏、发送结果持久化失败，不能先发再假装未接受；测试归 Task 15-C / 17-C。
