# OpenDesign UI 设计输入：智能日报只读页面

- 依据：已确认的 v1.1 proposal、design、ADR-004 和 HTTP 契约。
- 当前状态：首版与第二轮输入已通过 OpenDesign 0.24.1 UI 提交；产物及截图见 `opendesign-evidence.md`。
- 输入只含虚构团队、成员和记录；不读取真实配置、凭证或日报数据库。

## 首版输入（已在软件 UI 中提交）

请创建中文“智能日报”只读查看页面。用户通过有标签的日期输入选择日期，然后点击“查看日报”。不要添加侧边栏、统计图、成员管理、生成、推送、编辑、删除或登录操作。

有日报时显示“示例研发团队”、报告日期 2026-09-25 和生成时间 2026-09-25 18:00（UTC+08:00）。按顺序显示“示例成员甲”“示例成员乙”；每位成员固定三个板块：代码提交、任务进展、协作沟通。

成员甲的代码提交为“example/report：修正日期选择交互”，任务为“完成页面契约评审（已完成）”，消息为“日报：已完成只读页面原型”。成员乙三板块无记录时显示“今日无记录”，仍保留完整成员区段。

提供可演示的状态：查询前、加载中、正常日报、该日期尚无日报、查询失败（可重新查询）、任务来源失败（对应所有成员的任务板块显示“数据获取失败”）。HTTP 查询失败与日报来源失败分别表达，不能显示成同一种空状态。

视觉方向：简洁、清晰的工作阅读界面，深蓝标题与查询控件，浅灰背景和白色内容区，正文易读；使用分隔线与适度留白组织成员及三板块，手机上纵向排列。适配 375×812 与 1440×900，无页面级横向溢出。日期输入、查询和重新查询有可访问名称、明显键盘焦点。所有记录按文本呈现，链接只允许 HTTP(S)。

输出可预览原型和可保存的源文件/样式说明。这里是设计期虚构状态，最终产品必须查询真实 API，不得把 fixture 当作实际日报。

## 第二版实际输入（已在软件 UI 中提交）

请在现有 smart-daily-report.html 上完成第二轮 UI 迭代，只做以下可见调整：正文及记录从 15px 提高到 16px，报告日期标签从 13px 提高到 14px；日期输入和“查看日报”按钮从 44px 提高到 48px，按钮字体改为 16px，便于手机阅读和点击。保持深蓝/浅灰/白色、布局、六种演示状态与只读范围，不添加其他功能。确保 375×812 和 1440×900 无页面级横向溢出，长文本换行。修改完成后输出修改清单并保留同一 HTML 文件供导出；无需读取工作区其他文件。

原计划用第二轮区分页级无日报、板块空记录与来源失败；OpenDesign 首版已经落实这些要求，因此第二轮改为可核对的字体及控件尺寸调整。
