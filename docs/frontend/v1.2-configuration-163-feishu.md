# v1.2 逐步配置：163邮箱、GitHub与飞书

本指南对应隔离工作区 `E:\worktrees\v1-2-real-integration\smart-daily-report`。先读取真实来源、生成并核对预览，再由用户独立确认推送，最后核对实际收件。配置准备不等于真实验收通过。

## 1. 已准备的本机文件

`config.yaml` 从主目录既有本机配置复制，保留团队、仓库、成员与目标；已迁移旧飞书任务路径，并设置163隐式SSL。主目录配置未修改。准备时`.env`生成64位十六进制本机操作令牌、六项外部凭证留空；用户随后已填写七项凭证并通过本地校验。两个文件均被Git忽略；已有文件不会被准备操作覆盖。

打开工作区文件编辑。凭证只写.env；YAML保存的是 *_env 环境变量名。.env每行 KEY=VALUE，值不加引号，不加行尾注释。不要把密钥粘贴到聊天、截图、README或VITE_*。

| .env字段（实际名称以YAML为准） | 内容 |
|---|---|
| DAILY_REPORT_WEB_TOKEN | 已生成，保留；浏览器令牌输入框使用 |
| DAILY_REPORT_GITHUB_TOKEN | 能读取所选仓库的GitHub PAT |
| DAILY_REPORT_LARK_APP_ID | 飞书自建应用App ID |
| DAILY_REPORT_LARK_APP_SECRET | 同一应用App Secret |

以下按个人 @163.com 邮箱说明；网易企业邮箱需要另行核对服务器。

## 2. 开通163 SMTP并获取授权码

1. 登录 [163邮箱](https://mail.163.com/)。
2. “设置” → “POP3/SMTP/IMAP”（也可能显示“POP/SMTP/IMAP”）。
3. 开启包含SMTP的服务，例如“IMAP/SMTP服务”；按当前页面完成手机验证。
4. 将第三方客户端授权码填入.env的 DAILY_REPORT_SMTP_PASSWORD，使用授权码，不填网页登录密码。路径见 [华为官方163授权码指南](https://consumer.huawei.com/cn/support/content/zh-cn15872099/)。
5. DAILY_REPORT_SMTP_USERNAME填写完整发件邮箱，如 your-name@163.com。
6. 核对YAML的SMTP部分，将发件人和收件人改为本次确认的真实目标：

```yaml
  smtp:
    host: smtp.163.com
    port: 465
    username_env: DAILY_REPORT_SMTP_USERNAME
    password_env: DAILY_REPORT_SMTP_PASSWORD
    sender: your-name@163.com
    recipients: [your-confirmed-recipient@example.com]
    starttls: false
    use_ssl: true
```

sender应与登录邮箱一致。首轮可选你自己控制的收件邮箱，便于核对；recipients是列表，不保留未经本轮确认的旧收件人。服务器/端口见 [Lexmark官方邮件配置指南的网易邮箱表](https://publications.lexmark.com/publications/lexmark_hardware/MX822_MX826_XM7355_XM7370/UG/pdf/Lexmark_MX822_MX826_XM7355_XM7370_UserGuide_sc.pdf)。本项目465模式用 use_ssl: true / starttls: false，两项不能同时启用。

## 3. GitHub只读令牌和仓库

1. GitHub头像 → **Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**。
2. `Resource owner` 选择 `glufei`；设置有效期。`Repository access` 选择 **Only select repositories**，勾选 `smart-daily-report` 和仍需采集的 `Lab-Attendance-System`。
3. 在 **Repository permissions** 中将 **Contents** 设为 **Read-only**；Metadata 默认只读。不要申请写权限。组织要求审批时，需先由组织所有者批准。
4. 依据 [GitHub令牌创建文档](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)和 [提交列表读取权限](https://docs.github.com/en/rest/commits/commits#list-commits)；GitHub 文档要求读取提交时对目标仓库具有 Contents read。公共仓库可以匿名读取，私有仓库必须同时选入 Token 的仓库访问范围。
5. 创建后将新令牌填入 `.env` 的 `DAILY_REPORT_GITHUB_TOKEN`。不要把令牌发到聊天或截图；已有令牌只有在已授权这些仓库时才能复用。
6. YAML `github_repositories` 填 `owner/repository`，不填完整URL或 `.git` 后缀；成员 `github_logins` 填其GitHub用户名。
7. 本轮采集默认分支可达的提交；未推送到 GitHub 的本地提交不会出现在 API 结果中。核对日期、SHA和作者。

**本项目本机验收记录**：原仓库读取成功，新增的 `glufei/smart-daily-report` 返回 404，且匿名请求同样为 404；此结果与私有仓库未授权访问一致。需要完成上面的 Token 仓库授权，再将凭证注入后端窗口、重启服务并重新生成/预览。错误状态不是“没有提交”，授权通过后才可以继续核对记录。

## 4. 飞书自建应用：凭证、权限和发布

进入 [飞书开发者后台](https://open.feishu.cn/app)，选择你已有的自建应用。

1. 在“凭证与基础信息”等对应页面查看App ID / App Secret，填入.env，两项来自同一应用。
2. 若读取群消息需要应用机器人，启用其机器人能力，并将该应用机器人加入需要读取的来源群。
3. 在官方接口文档的“权限要求”和API调试台核对租户需要的最小读取权限：
   - [获取任务清单中的任务列表](https://open.feishu.cn/document/task-v2/tasklist/tasks)：GET /open-apis/task/v2/tasklists/{tasklist_guid}/tasks。
   - [获取会话历史消息](https://open.feishu.cn/document/server-docs/im-v1/message/list)：GET /open-apis/im/v1/messages。
4. 应用“权限管理”申请接口明确要求的权限，按租户要求处理清单和群消息的数据访问范围。
5. 在“版本管理与发布”创建并发布版本，完成所需审批，再在API调试台确认生效。草稿里勾选权限不足以证明正式请求可访问。

2026-10-01真实任务接口已返回HTTP400/业务码99991672，明确要求 task:tasklist:read 或 task:tasklist:write。本项目只读取，申请 task:tasklist:read，按 [权限开通与发布步骤](feishu-tasklist-permissions.md) 操作。用户已开通并发布，重新获取租户Token后列取清单HTTP200/code0，读取scope已生效；旧配置误填任务GUID已修正；清单初次GET403，用户通过用户身份调试台添加当前自建应用为viewer后，tenant身份详情/任务GET200/code0，2026-10-01真实完成任务1条且负责人映射通过。清单链接区分见权限指南第5节，当前资源授权步骤见第6节；不申请无关权限，不发送密钥截图。

后端用App ID/Secret自动获取和刷新 tenant_access_token。调试台应选同一应用的租户身份；个人 user_access_token 调试成功不能证明本项目可访问。租户身份读取失败时，先确认访问主体和清单对应用的授权，保留为联调阻塞项，不静默换个人Token。

## 5. 核对飞书来源ID和成员映射

旧配置值已保留，仍需逐项确认。

**任务清单**：在API调试台用官方“列取任务清单”等读取接口查看该应用可访问的清单，或从已授权清单接口响应确认guid。再调试目标清单的任务列表，page_size=100、completed=true、user_id_type=open_id。必须是租户身份成功读取目标清单。

```yaml
  lark_project_ids: [实际tasklist_guid]
  lark_task_search_path: /task/v2/tasklists/{tasklist_guid}/tasks
```

lark_project_ids为兼容保留的字段名，实际填写任务清单GUID，不能填项目ID、单条任务GUID或群ID。任务按completed_at和团队时区筛选所选日完成的记录；0或其他日期不进入日报，不推断旧状态。

**来源群**：调试台用“获取群列表”等读取接口核对应用机器人所在群和chat_id，再调试历史消息，container_id_type=chat、container_id=该chat_id。

```yaml
  lark_chat_ids: [实际oc_群ID]
  report_keywords: [日报, 进展, 发布]
  sensitive_keywords: [薪资, 绩效]
```

这是采集来源群，与Webhook推送目标分别配置。名称或邀请链接不能替代chat_id。消息须命中工作关键词；敏感词命中的整条消息被排除。不为获得非空结果删除敏感过滤。

**成员**：从同一应用真实任务的负责人members[].id（type=user、role=assignee），或消息sender.id核对实际成员，填入lark_user_ids。使用同一应用下的open_id，通常ou_开头；不要混用其他应用ID、user_id、union_id。

```yaml
members:
  - member_id: member-001
    display_name: 你的姓名
    github_logins: [你的GitHub用户名]
    lark_user_ids: [同一应用下ou_用户ID]
    github_author_names: []
```

member_id不能重复，同一外部账号不能分给两个成员。读取成功却显示成员无记录时，先核对映射和筛选条件。

## 7. 选择真实验收日期

选择一个真实工作日YYYY-MM-DD，确认有GitHub提交、目标清单当日完成任务、符合过滤规则的群消息及成员映射。缺少非空任务就不能宣称非空任务验收通过，可选另一个有数据的工作日。

## 8. 加载凭证、校验与启动

PowerShell窗口A执行（加载过程不打印值）：

```powershell
Set-Location 'E:\worktrees\v1-2-real-integration\smart-daily-report'
$env:PYTHONPATH = Join-Path (Get-Location) 'src'
Get-Content -LiteralPath '.env' | ForEach-Object {
    $entry = $_.Trim()
    if ($entry -and -not $entry.StartsWith('#')) {
        $separator = $entry.IndexOf('=')
        if ($separator -lt 1) { throw 'Invalid .env line: expected KEY=VALUE' }
        [Environment]::SetEnvironmentVariable(
            $entry.Substring(0, $separator).Trim(),
            $entry.Substring($separator + 1),
            'Process'
        )
    }
}
```

程序不自动读取.env；修改后重新加载并重启后端。窗口B不需要外部凭证。复用main的Python环境，PYTHONPATH指向工作区，避免加载旧代码。

先做本地校验，不访问外部、不创建数据库、不发送：

```powershell
& 'E:\MyCode\smart-daily-report\.runtime\venv\Scripts\python.exe' -c 'import os; from pathlib import Path; from smart_daily_report.shared.config import load_config; from smart_daily_report.web.operations import validate_operation_config; config=load_config(Path("config.yaml")); validate_operation_config(config, os.environ.get("DAILY_REPORT_WEB_TOKEN", "")); print("Local configuration valid; upstream access and receipt not verified")'
```

这只验证程序要求的配置，不证明源ID、目标、外部权限或SMTP登录。SMTP login requires both configured credential variables表示未填齐SMTP登录邮箱/授权码，或未重新加载。

填写齐全后可运行已有连通性检查：

```powershell

```

它访问真实GitHub/飞书、连接SMTP，不生成、不写日报、不发通知。SMTP只检查连接不验证登录；Webhook只检查配置存在。分别核对lark_tasks_1 / lark_messages_1，Token成功不等于数据可读。失败保留脱敏错误及布尔结果，不复制完整私密响应。

## 9. 预览与真实收件验收

1. 从.env复制本项目DAILY_REPORT_WEB_TOKEN到浏览器，点“验证令牌”；其他密钥留在后端。
2. 选日期，点“采集并生成”：真实采集、保存和预览，发送0次。
3. 核对三部分、成员归属、来源状态和日期。来源失败与正常零记录分开。
4. 核对固定邮箱/群和版本摘要，独立选SMTP/飞书，点“推送日报”，检查确认框后确认；取消不发送。
5. 核对渠道结果，以及邮箱（含垃圾邮件）和目标群的实际内容；accepted仅表示服务商受理。
6. unknown先查执行结果/实际收件，勿反复发送；只有明确rejected渠道按页面允许单独重试。不要删除operations.sqlite3解除重发保护。
