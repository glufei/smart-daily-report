# v1.3.0 发布后维护复核

日期：2026-10-11。范围是 Task22 中列出的维护缺项。此文记录未发布的维护分支工作，不更改或追溯修改 v1.3.0 发布物。测试数据全部为合成数据；未调用 GitHub/飞书生产 API、SMTP 或 webhook，未使用真实配置或日报数据库。

## 发现与修复

| 项目 | 根因 | 最小处理 |
| --- | --- | --- |
| 操作面板永久忙碌 | 验证令牌、生成/推送提交和操作后附带预览没有统一的网络等待上限；异常慢请求可永不结束 | 对这些请求设 10 秒上限，超时后解除忙碌并提示用户。生成/推送 POST 未确认时保留原请求键，允许查询原操作，不自动重发。 |
| GitHub commit 分页循环 | 主 commit 列表只信任 `Link: next`，没有记录已请求页面；上游重复链接会循环请求 | 每个仓库记录已访问页面 URL；再次遇到即以 `invalid_pagination` 失败，不返回部分记录。 |
| 外部身份字段类型不可信 | GitHub `author.login`/`commit.author.name` 与飞书 `sender.id`/`sender.sender_id` 被不验证地写入模型；后续身份映射的字符串操作可能逃逸到全局 `internal_error` | 在采集器边界校验非空值必须是字符串；违反时以来源级 `invalid_payload` 失败，其他健康来源仍可生成日报。 |
| 前端开发依赖安全公告 | 锁文件固定 `source-map-js` 1.2.1，低于已公告的修复版本 | 只更新锁文件到 1.2.2；上游声明修复版本为 1.2.2，见 [GitHub Advisory GHSA-68fv-2mgg-jv7q](https://github.com/advisories/GHSA-68fv-2mgg-jv7q)。 |
