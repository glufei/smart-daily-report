## 4. 发现的问题与处理

| 编号 / 级别 | 发现与根因 | 处理与验证 |
| --- | --- | --- |
| H01 / Important | `--check` 对任务/消息 HTTP 200 响应使用缺失码默认 0；布尔值或浮点 0 也可能被判成功，与采集器冲突 | 先增加两来源 14 个参数用例；正确 RED 为 8 failed、6 passed、exit 1。再要求字典、`type(code) is int` 且为 0；合法空页继续健康，缺失/错误类型/错误码失败。原成功 fixture 改为合法平台响应；该文件 33 passed，完整后端 300 passed |
| H02 / Important | 只读 Playwright 服务继承父进程 `VITE_API_MODE=operations`，查询后 Tab 错到令牌输入框 | 现有键盘用例在该环境出现真实焦点断言失败；没有改断言或业务交互。只为只读测试服务固定 readonly。RED 及首轮 GREEN 均在受限环境中等待子进程清理，Ctrl+C 后 exit 1，未记为自然完成的测试运行；允许正常清理后，相同父环境全套 14 passed、exit 0 |
| H03 / Minor | 设计、接口、配置指南和运行说明混用旧“待实现/待验收”及 v1.1 测试数字 | 当前说明校正；原 checkpoint 标记为历史并保留，README 增加本交付入口 |
| H04 / Minor，保留 | 启动校验未强制限定操作令牌可传输字符集；Unicode、换行或首尾空格可能导致浏览器头构造/认证失败 | 使用 README 推荐的 `secrets.token_hex(32)` 生成 64 位 ASCII 十六进制令牌，避免问题；明确记录限制，未扩大修改鉴权。现有安全比较使用 bytes，没有发现鉴权绕过 |

H01 的修复不意味着完整健康检查等同于端到端验收：SMTP 连接和 NOOP 不证明授权码登录、发送及收件，Webhook 配置存在不证明机器人可受理消息；仍须按配置指南和真实验收流程核对。

## 6. 保存、停止与维护

- 两个服务窗口分别按 Ctrl+C 停止；启动服务本身不生成或推送。
- 私有 `.env`、`config.yaml`、数据库和真实页面截图不提交 Git。浏览器只输入本项目操作令牌，不接收 GitHub Token、飞书 Secret、SMTP 授权码或 Webhook。
- 备份先停止写入服务，再同时备份配置指定的日报 SQLite 和同目录 `<日报库文件名>.operations.sqlite3`，以及必要的 `.env`/`config.yaml`。前者保存内容，后者保存幂等键、操作与渠道记录；两者应一致恢复，不能删除操作库来解除重发保护。
- 推送断线先查原操作结果；unknown、partial_failure 或 pending 先核实实际收件，不能猜测重发。重新生成不构成已发送内容的重发许可。
- 本项目为 loopback、单 Uvicorn worker；不用 reload，不与 CLI 并发写同一套业务数据，不向公网或局域网暴露当前维护令牌模式。

## 7. 验证边界与后续工作

已确认范围没有待补业务模块。以下是有意保留的限制或尚未进行的额外验证，不冒充已经通过：

- 真实限流、多页任务和飞书客户端特殊字符实发未逐项在线验证；对应确定性分支有离线测试。
- 原始“5 人完整流程小于 60 秒”目标尚未进行端到端负载验证。现有 `test_five_member_generation_meets_sixty_second_budget` 只计时 `generate_daily_report`，不包含外部采集及完整管道；已有真实生成小样本也不能替代该目标的负载验收。
- 浏览器自动验收为已安装 Chrome 的 375×812 / 1440×900 视口；没有声称覆盖 Firefox、Safari、所有实体手机。
- 法定假日仅依配置日历判断，不推断国家调休；飞书任务展示当前授权清单中所选完成日期，不重建任意历史状态变化。
- 多实例部署、跨进程统一排他、OAuth、队列服务和公网权限体系不在本轮范围。
- H04 的令牌字符集启动加固可作为维护任务；目前遵循推荐 ASCII 生成方式即可运行。
- 若希望标签安装也包含本次审查补丁，后续可单独规划维护版本；现有 v1.2.0 标签保持原提交。
